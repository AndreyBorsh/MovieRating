# Развёртывание WAW на своём сервере (Docker)

Весь стек — база данных (PostgreSQL), бэкенд (FastAPI) и фронтенд (Next.js) —
поднимается одной командой через Docker Compose. Vercel / Render / Railway
больше не нужны.

## Что нужно на сервере

- Docker Engine + плагин Docker Compose (`docker compose version` должен работать).
- Открытый порт для сайта (по умолчанию `3000`).

## Первый запуск

```bash
# 1. Клонировать репозиторий
git clone <ваш-репозиторий> waw
cd waw

# 2. Создать .env из примера и вписать реальные значения
cp .env.example .env
nano .env          # обязательно смените POSTGRES_PASSWORD

# 3. Собрать и запустить весь стек в фоне
docker compose up -d --build
```

Сайт будет доступен на `http://<IP-сервера>:3000` (или на порту `WEB_PORT` из `.env`).

При первом старте бэкенд сам создаёт все таблицы в пустой базе — миграции
запускать не нужно.

## Переменные окружения (`.env`)

| Переменная          | Обязательна | Описание                                                        |
| ------------------- | ----------- | --------------------------------------------------------------- |
| `POSTGRES_PASSWORD` | да          | Пароль БД. Обязательно смените со значения по умолчанию.         |
| `POSTGRES_USER`     | нет         | Пользователь БД (по умолчанию `waw`).                           |
| `POSTGRES_DB`       | нет         | Имя БД (по умолчанию `waw`).                                    |
| `ADMIN_USER_IDS`    | нет         | ID админов через запятую (по умолчанию `1` — первый юзер).       |
| `LLM_API_KEY`       | нет         | Ключ OpenRouter для проверки рецензий. Пусто — функция выключена. |
| `BREVO_API_KEY`     | нет         | Ключ Brevo для писем-подтверждений. Пусто — письма выключены.    |
| `BREVO_SENDER`      | нет         | Email отправителя для Brevo.                                     |
| `WEB_PORT`          | нет         | Порт сайта на хосте (по умолчанию `3000`).                       |

## Обновление сборки (деплой новой версии)

```bash
git pull
docker compose up -d --build
```

Compose пересоберёт изменённые образы и перезапустит контейнеры. Данные в базе
сохраняются (лежат в Docker-томе `db_data`).

## Полезные команды

```bash
docker compose logs -f              # логи всех сервисов
docker compose logs -f backend      # логи только бэкенда
docker compose ps                   # статус контейнеров
docker compose down                 # остановить (данные БД сохраняются)
docker compose down -v              # остановить и УДАЛИТЬ базу (том db_data)
```

## Про данные из Railway

База, которая крутилась в Railway, здесь не переносится автоматически — стартуете
с чистой БД, таблицы создаются заново. Если есть дамп из Railway (`pg_dump`),
восстановить можно так:

```bash
# 1. Временно открыть порт БД: раскомментировать блок `ports: 5432:5432`
#    у сервиса db в docker-compose.yml, затем: docker compose up -d db
# 2. Залить дамп
psql "postgresql://waw:<пароль>@localhost:5432/waw" < backup.sql
# 3. Закрыть порт обратно (закомментировать) и поднять остальное:
docker compose up -d --build
```

Дамп можно снять из старого Railway, пока он ещё доступен:
`pg_dump "<RAILWAY_DATABASE_URL>" > backup.sql`

## Архитектура

```
              ┌─────────────┐
  браузер ──▶ │  frontend   │  Next.js, порт 3000 (наружу)
              │ (Next API   │
              │  proxy)     │──┐  http://backend:8000  (внутренняя сеть)
              └─────────────┘  │
                               ▼
                        ┌─────────────┐
                        │   backend   │  FastAPI, порт 8000 (внутри сети)
                        └─────────────┘
                               │  postgresql://db:5432
                               ▼
                        ┌─────────────┐
                        │     db      │  PostgreSQL, том db_data
                        └─────────────┘
```

Фронтенд проксирует запросы на бэкенд через внутреннее имя `backend`, поэтому
наружу торчит только порт сайта. Бэкенд и БД в интернет не выставлены.
